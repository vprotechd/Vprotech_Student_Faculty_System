# Student–Faculty–Admin Portal API

## Setup
1. Install Node.js 20+ and MongoDB (local or Atlas).
2. Copy `.env.example` to `.env` and set `MONGO_URI` and a random `JWT_SECRET` (at least 32 characters).
3. Run `npm install`, then `npm run dev` from this directory.
4. Health check: `GET http://localhost:5000/api/health`.

## Authentication
- `POST /api/auth/register` or `/api/auth/signup` — student registration only; body `{ "name", "email", "password" }`.
- `POST /api/auth/login` — body `{ "email", "password", "role" }` (role optional).
- `GET /api/auth/me` — Bearer token required.
- Successful auth response shape: `{ success, message, data: { user, token } }`.

Passwords must be at least 12 characters and include upper/lowercase, number and special character. Faculty/admin accounts are provisioned through the authenticated admin API, never through public registration. To create the first administrator, set `ADMIN_NAME`, `ADMIN_EMAIL`, and `ADMIN_PASSWORD` in `.env`, then run `npm run seed:admin` once. Remove those values from `.env` after seeding.

## API modules
`/api/admin`, `/api/students`, `/api/faculty`, `/api/departments`, `/api/courses`, `/api/subjects`, `/api/classes`, `/api/lectures`, `/api/materials`, `/api/timetable`, `/api/doubts`, `/api/notifications`, and `/api/classrooms`. Resource endpoints support authenticated paginated `GET /`, `GET /:id`, `POST /`, `PATCH /:id`, and `DELETE /:id`, with role restrictions. `GET /api/admin/dashboard`, `GET /api/admin/users`, `POST /api/admin/users`, and `PATCH /api/admin/users/:id/status` are admin-only.

## Live classroom
Set `AGORA_APP_ID` and `AGORA_APP_CERTIFICATE` in the backend environment. The certificate is used only by the backend to issue short-lived RTC tokens and must never be added to the Expo app. Faculty can start a class only for their own active timetable entry on the current date; students can join only when their course, semester, and section match and the faculty has started it. Chat uses the authenticated Socket.IO connection, while attendance is recorded on join and updated on leave, disconnect, or class end.

The mobile app requires a native development build; Agora's native module does not run in Expo Go. Rebuild the native app after changing permissions or dependencies. Android screen sharing uses the system screen-capture prompt. iOS screen sharing requires a ReplayKit broadcast-upload extension and app-group configuration, which are not generated by this project; the app reports that limitation instead of pretending screen sharing is available.

## Mobile emulator / device
`EXPO_PUBLIC_API_URL` is optional: leave it unset to use the frontend's platform defaults (`http://10.0.2.2:5000/api` for Android emulator and `http://localhost:5000/api` for web/iOS simulator). Set it only to override those defaults, such as `http://YOUR_LAN_IP:5000/api` for a physical phone. Set `CLIENT_ORIGINS` for web origins as a comma-separated list.

Test fixture routes are disabled by default. To enable locally only, set `ENABLE_TEST_ROUTES=true`; never enable them in production.
